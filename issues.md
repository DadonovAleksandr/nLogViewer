# Issues: улучшения и технический долг nLogViewer

## 1) Нарушение MVVM: создание UI-элементов во ViewModel
- Описание: `MainWindowViewModel` создает `TabItem`, `ContextMenu`, `MenuItem` и управляет визуальными элементами.
- Риски: сильная связность, плохая тестопригодность, нарушение SRP/SOLID.
- Предлагаемое решение:
  - Перенести заголовок вкладок и контекстное меню в XAML через `DataTemplate`/`ContextMenu`.
  - Во VM оставить только `ICommand` (например, `OpenInNotepad`, `OpenInExplorer`, `OpenInNotepadPP`) с параметром пути.

## 2) Глобальное состояние в `FileLogReaderConfiguration`
- Описание: `FileName` хранится в статическом поле.
- Риски: гонки, проблемы с несколькими инстансами, сложность тестирования.
- Решение: передавать путь в фабрику/репозиторий параметром, отказаться от статики.

## 3) Протекающая абстракция в `ILogViewer`
- Описание: `LogEntries` возвращает `List<ILogEntry>` (мутабельная конкретика).
- Решение: заменить на `IReadOnlyList<ILogEntry>` или `IEnumerable<ILogEntry>`, запретить внешнюю мутацию.

## 4) Несогласованность sync/async для очистки
- Описание: существуют `Clear()` и `ClearAsync()`, в некоторых местах используется `.GetAwaiter().GetResult()`.
- Риски: блокировки UI, дедлоки.
- Решение: сделать очистку сквозной асинхронной (команда UI → `await _viewer.ClearAsync()`), убрать синхронные блокировки.

## 5) Избыточные диалоги ошибок при парсинге
- Описание: показ `ShowError` на каждую проблемную строку.
- Риски: спам UI, деградация UX.
- Решение: логировать ошибки, агрегировать и показывать ограниченно (троттлинг), либо только лог-файл/статусную строку.

## 6) Таймер + async (fire-and-forget)
- Описание: `TimerCallback(async ...)` запускает фоновые задачи без управления жизненным циклом.
- Риски: гонки, непредсказуемость.
- Решение: перейти на `PeriodicTimer` или явный цикл с `await` и корректной отменой; альтернативно `DispatcherTimer` для UI-задач.

## 7) Дублирование стеков чтения/парсинга
- Описание: параллельно используются `FileLogReader` и репозитории (`RepositoryLogSource`).
- Риски: поддержка двух реализаций, расхождение логики.
- Решение: консолидировать на репозиториях, удалить/законсервировать старый код.

## 8) Очистка файла лога и шаринг дескрипторов
- Описание: очистка через `FileMode.Create` и узкий `FileShare` конфликтует с писателями.
- Решение: открыть файл с `FileShare.ReadWrite | FileShare.Delete` и выполнить `SetLength(0)`; добавить несколько ретраев с backoff; сбрасывать позицию чтения у репозитория/ридера.

## 9) Поиск Notepad++
- Описание: поиск только в Program Files и PATH.
- Решение: дополнительно проверять реестр `HKLM/HKCU\Software\Notepad++` и `DisplayIcon` из Uninstall-записей.

## 10) Прогресс больших файлов
- Описание: эвристика порога 10 МБ и прогресс «по количеству записей».
- Решение: вычислять прогресс по байтам файла; сглаживать отображение; порог настраивать в конфиге.

## 11) Событие `EntriesChanged` без аргументов
- Описание: отсутствие информации о диапазонах/количестве изменений.
- Решение: заменить на `EventHandler<EntriesChangedEventArgs>` с данными (кол-во, диапазон), оптимизировать обновление `DataGrid`.

## 12) Предупреждения nullable (`CS86xx`)
- Описание: многочисленные варнинги по nullability в VM/сервисах.
- Решение: выровнять аннотации nullable, добавить guard-условия, скорректировать сигнатуры интерфейсов.

## 13) Закрытие окна прогресса из фоновой задачи
- Описание: окно закрывается через фоновые задержки/`DialogResult`.
- Риски: гонки, непредсказуемость.
- Решение: закрывать окно на UI-потоке после `await` операции; убрать «секундные» задержки.

## 14) Конфигурация памяти (виртуализация)
- Описание: параметры виртуализации в DI выставлены «временно» в false.
- Решение: вынести в `appsettings.json`/UI-переключатели; включать по умолчанию там, где оправдано.

## 15) Соответствие интерфейсам коллекций и nullability
- Описание: несоответствия сигнатурам (`IList`/события), варнинги CS8767/CS8612.
- Решение: привести сигнатуры к корректным nullable-аннотациям; избегать несоответствий при явных/неявных реализациях.

## 16) `LogRepositoryFactory` расширяемость
- Описание: жёсткое допущение по кодировке/типам.
- Решение: добавить поддержку кодировок в конфиг, предусмотреть будущие источники (HTTP/DB) через интерфейсы и адаптеры, не бросая `NotImplementedException` в прод-коде.

## 17) Обработка отсутствующих/удалённых файлов
- Описание: возможны состояния гонки при исчезновении файла.
- Решение: устойчиво обрабатывать `FileNotFound/IO` без всплывающих диалогов, с авто-повтором и уведомлением в статусе.
